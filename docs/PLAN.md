# yt: YouTube subscriptions in Emacs (implementation plan)

> Status: final plan, written 2026-10-31. Five planning agents wrote it and ten judge agents reviewed it. Appendix A lists every review finding and what was done with it.

## 0. Goals, decisions, environment

### Requirements
1. Use the user's logged-in YouTube account to see their subscriptions.
2. The default home view is a list of subscription-feed videos.
3. Videos play either in an mpv window that Emacs controls, or by streaming to VLC.

### Decisions
| Topic | Decision |
|---|---|
| Name | Package, feature, and main file are all `yt` (`yt.el`, prefix `yt-`, `M-x yt`). The repo directory stays `~/dev/emacs-yt`. The code is written to MELPA standards (package-lint, checkdoc, ERT, compiles with no warnings), but it won't be submitted to MELPA under this name. |
| Auth | yt-dlp with cookies from a **dedicated ungoogled-Chromium profile** that is signed in only to YouTube. No OAuth, no API keys. |
| Playback | `yt-player-backend` defaults to `auto`: mpv if it is installed, otherwise VLC. mpv runs as one long-lived process in its own sway window, driven over JSON IPC. VLC is fire-and-forget: Emacs resolves the stream URLs and hands them over. |
| Scope | The full feature set in §12, delivered milestone by milestone. VLC comes before mpv so that all three requirements work as early as possible. |
| Nix | The project's `flake.nix` supplies every external tool: the dev shell, a test Emacs, a sandbox Emacs, the cookie exporter, mpv, and checks. |
| Testing | Tests always use a **separate Emacs from the flake** with an isolated HOME and XDG directories. They never use the host Emacs, `~/.emacs.d`, or the running daemon (§11). |
| Emacs floor | `Package-Requires: ((emacs "30.1"))`. Native JSON parsing is always available from 30.1 (29.1 needs libjansson), and 30.1 is the only version tested. |

### Verified environment (2026-10-31)
- **System:** NixOS, with the dotfiles flake tracking `nixos-26.05`, running sway on Wayland. The dotfiles flake builds 6 hosts.
- **Emacs:** 30.2 `emacs-pgtk`, with native-comp and SQLite, no xwidgets.
- **Emacs config:** minimal-emacs.d plus straight.el.
  - The config is generated by home-manager from `~/dotfiles/nix/assets/emacs.d/post-init.el`. `~/.emacs.d/*.el` are read-only store symlinks.
  - `use-package-always-ensure` is `t`.
  - `custom-file` is `~/.emacs.d/custom.el`, and it is **never loaded**.
  - which-key is on. repeat-mode is off. `C-c y` is free.
- **Emacs daemon:** runs as a systemd user service started from `default.target`, so it starts before sway. Its environment has PATH and XDG_RUNTIME_DIR, but **no WAYLAND_DISPLAY**. XDG_STATE_HOME is unset.
- **yt-dlp:** 2026.10.21 from nixpkgs, via `desktop-apps.nix`.
  - Its wrapper bundles **deno 2.8.3** (`yt-dlp -v` reports "JS runtimes: deno-2.8.3"), along with secretstorage and yt_dlp_ejs. No `--remote-components` is needed.
  - No ffmpeg is needed, because the players merge audio and video themselves.
- **vlc:** on PATH. **mpv:** not installed. nixpkgs 26.05 ships mpv 0.41.0, which supports `--wayland-app-id`.
- **Keyring:** on sway, yt-dlp's automatic keyring detection picks `basictext`, but `gnome-keyring-daemon` is running. This is why the exporter reports the keyring explicitly (§4.2).

**No external elisp dependencies.**
- empv and mpv.el were rejected: empv brings its own Invidious UI and global state, and mpv.el uses the legacy `json` library and `tq`.
- yeetube, ytdious, and elfeed-tube only do search or RSS, not authenticated feeds.
- The Commentary credits empv and mpv.el as prior art. If any code is adapted from them, their GPL copyright notices are kept.

**Dependency graph** (strictly downward). Changed in M1: `yt-auth` depends on `yt-ytdlp`, not the other way round. Verifying a login has to run yt-dlp, so `yt-auth-run` (which runs yt-dlp with a per-run cookie copy) lives in `yt-auth`, and `yt-ytdlp` keeps only argument lists, the classifier and the version check:
```
yt-feed ─> yt-auth ─> yt-ytdlp ─> yt-process
   │   └─> yt-cache ─> yt-video
   └─> yt-player ─(lazy require by backend symbol)─> yt-mpv | yt-vlc
yt-mpv/yt-vlc ─> yt-player, yt-ytdlp, yt-cache
yt-info, yt-select, yt-doctor ─> yt-feed helpers, yt-player
every module ─> yt (customs + keymaps only); yt.el requires nothing
```

**Autoloads:**
- Every command bound in `yt-map` or `yt-player-map` gets `;;;###autoload`. `yt-map` and `yt-player-map` are defined in `yt.el`, so the keymaps work before anything else is loaded.
- `:repeat` maps live in `yt-player.el`.
- Cross-module lazy calls use `declare-function`.

## 2. Data model (`yt-video.el`)
```elisp
(cl-defstruct (yt-video (:constructor yt-video--make) (:copier nil))
  id title channel channel-id channel-url
  duration            ; seconds or nil (nil for live/upcoming/Shorts in flat mode)
  timestamp           ; epoch; "timestamp" > "release_timestamp" > "upload_date"
  timestamp-approx-p  ; t if from youtubetab:approximate_date
  views live-status   ; symbol: not_live/is_live/is_upcoming/was_live/post_live
  thumbnail url short-p
  fetched-at watched position)  ; local state from yt-cache
```
- **Conversion:** `yt-video-from-json PLIST`. All JSON is parsed with `:object-type 'plist :array-type 'list :null-object nil :false-object nil`. Use `plist-member` to tell a missing key from a nil value.
- **Shorts:** detected **by URL only** (`/shorts/`). Flat Shorts entries come from `shortsLockupViewModel` and contain only id, url, title, view_count, and thumbnails. Every channel accessor must therefore handle nil.
- **`view_count` is usually missing.** It was absent in all 30 real feed entries during the M0 spike, so the Views display is optional.
- **Sorting (changed by the M0 spike):** the subscriptions feed is sorted by **feed position**, which is stored per fetch. The approximate timestamps are rounded from "N hours ago" and are not monotonic in feed order, so they are used for display only. Channel uploads and merged caches still need a time key, and for that the order `(or timestamp inherited-ts fetched-at)` applies:
  - An entry without a timestamp, which includes all Shorts, borrows the timestamp of the entry just before it in feed order. This keeps a first fetch from putting every Short at the top.
  - A cached exact timestamp is never overwritten by an approximate one.
- **Clock:** `yt--now` is a `defvar` holding a function, defaulting to `float-time`. All relative-time code calls it, so tests can control the clock.

## 3. Async process layer (`yt-process.el`)
```elisp
(cl-defun yt-process-run (program args &key on-success on-error on-line
                                  (parse 'json) timeout key env) ...) ; -> process
(defun yt-process-cancel (key-or-proc) ...)
(defun yt-process-busy-p (key) ...)
(defun yt-process-queue-run (queue thunk) ...) ; counting semaphore (info pass: 2, thumbs: 4)
```
- **make-process arguments:** `:connection-type 'pipe :coding 'utf-8-unix :noquery t`, with `:stderr` set to a `make-pipe-process` that also has `:noquery t`. `ENV` is prepended to `process-environment`.
- **NDJSON mode:** the filter collects partial lines and calls **`ON-LINE` synchronously**, wrapped in `condition-case`.
  - If `ON-LINE` returns `'stop`, the runner sets a per-process `stopped` flag, drops every later line (including the rest of the current chunk), and calls `interrupt-process`.
  - When `stopped` is set, the exit counts as success. yt-dlp exits 1 with "Interrupted by user" in this case, so the flag is checked before the exit code is classified.
- **Finalize** runs exactly once, after **both** the main process has exited **and** the stderr pipe has closed, with a 0.5 s fallback timer after the main exit. A deno grandchild can keep the pipe open, which is why the fallback exists. Finalize then:
  1. cancels the timeout timers,
  2. deletes the stderr pipe,
  3. classifies the stderr text, which includes `WARNING:` lines **on every exit**, including exit 0,
  4. schedules `on-success` / `on-error` with `run-at-time 0`,
  5. kills the buffers in `unwind-protect`.

  `accept-process-output` is never called inside a sentinel.
- **Error plist:** `(:type exit|parse|timeout|cancelled|missing :class CLASS :exit-code N :stderr STR)`.
- **Single-flight keys** are structured, for example `(feed . subscriptions)` or `(feed . (:channel ID))`.
  - A duplicate call with a live key just shows a message.
  - A *forced* call (`G`) cancels the running process and restarts.
  - `kill-buffer-hook` cancels the buffer's in-flight processes.
- **Timeouts:** `yt-process-timeout` (default 120 s). On timeout the runner sends SIGINT, then SIGKILL after `yt-process-kill-grace` (a `defvar`, 5 s, set shorter in tests).
- **Logging:** argv is written to `*yt-log*`, with search queries redacted. Cookie contents are never written to the log, an error message, or a buffer that is still alive.

## 4. Auth and yt-dlp (`yt-auth.el`, `yt-ytdlp.el`, `bin/yt-export-cookies`)
### 4.1 Base args
`--ignore-config --color never --no-progress --socket-timeout 20 --cookies <per-run copy>`

Each builder appends its own flags, then **`--`**, then the URL.

**Never passed:** `--no-warnings` (auth signals arrive as warnings), `--compat-options`, `-v`/`--verbose`, `--print-traffic`, `--dump-pages`, `--write-pages`, `--load-pages`, `--write-info-json`. `yt-ytdlp-extra-args` has type `(repeat string)` and is checked against that denylist, plus `--cookies*`, `--print` and `-O`, at the moment it is used.

### 4.2 Cookies: dedicated profile, exporter, master file, per-run copies
**One-time setup (README):**
1. In ungoogled Chromium, *Add profile* and name it `emacs-yt`.
2. Sign in to YouTube in that profile only.
3. Run `M-x yt-login`.

**Profile selection:**
- `yt-login` reads `~/.config/chromium/Local State` (`profile.info_cache`, which maps directory to display name). It offers a completing-read over the profiles, preselecting one named `emacs-yt`.
- If the user picks `Default`, `yt-login` shows a warning and asks for confirmation.
- The choice is saved in `state.eld` in `yt-state-directory` (mode 0600, replaced atomically; `yt-state-get` / `yt-state-put` in `yt.el`). It was planned for the cache `meta` table, but the cache only arrives in M2 and this small state doesn't need SQLite. It is **never** saved through `customize-save-variable`.
- `yt-cookie-profile` is a user override with type `(choice (const :tag "Ask" nil) string)`.
- Nothing is probed silently.

**Exporter, `yt-export-cookies`:** a roughly 60-line Python script packaged by the flake with `python3.withPackages (ps: [ ps.yt-dlp ps.secretstorage ])`.
- It calls `yt_dlp.cookies.extract_cookies_from_browser("chromium", PROFILE, logger, keyring=K)`, trying `K` = `GNOMEKEYRING` and then `BASICTEXT` (plain `chromium` is the same as basictext on sway, so it is dropped).
- It uses a capturing logger, so the decrypt-failure counts are visible. yt-dlp's own "Extracted N cookies" output is hidden under `-J`.
- It keeps only cookies whose domain is exactly `youtube.com`, `.youtube.com`, or ends with `.youtube.com`.
- It writes a Netscape file through `os.open(tmp, O_CREAT|O_EXCL|O_WRONLY, 0o600)` in the 0700 state directory, followed by `fsync` and `os.replace`.
- On stdout it prints one JSON summary: `{"keyring":K,"count":N,"decrypt_failures":F,"has_login_info":b,"has_sapisid":b}`. It never prints cookie values.

This design means **no file holding all browser cookies ever exists**. Running `--cookies-from-browser X --cookies TMP` through yt-dlp would write every cookie for every site.

**Login flow (`yt-login`):**
1. Choose the profile.
2. Run the exporter. A `keyring` error is reported when `decrypt_failures > 0` or `has_sapisid` is false, together with the next suggestion (open Chromium in that profile, or unlock the keyring).
3. Verify with a separate call: `<base> --flat-playlist -I 1:3 -J -- :ytsubs`. This counts as success only on exit 0, with at least one entry, and no "no longer valid" warning.
4. Set `yt--auth-state` to `ok`.

**Files** (`yt-state-directory` = `(expand-file-name "yt" (xdg-state-home))`, mode 0700):
- `cookies.txt` is the **master** file. It is written only by the exporter or by an atomic write-back, and **yt-dlp never touches it directly**.
- **Every run** gets a private copy in `yt-runtime-directory`, which is `$XDG_RUNTIME_DIR/yt/` (tmpfs, 0700). Emacs checks that this directory is owned by the user and has mode 0700, and refuses to use it otherwise. There is no fallback to /tmp.
- The copy is created with `(with-file-modes #o600 …)` followed by an explicit `set-file-modes #o600`. Directories use `#o700`. Tests assert `(file-modes f)`.
- **Write-back:** after an exit-0 run, if the copy has the header and contains `LOGIN_INFO` and SAPISID, and `yt-auth--generation` hasn't changed since the run started, the copy is renamed atomically into the master. Only one writer at a time is allowed, using a single in-Emacs mutex. This keeps cookies that YouTube rotated during the run (`__Secure-*PSIDTS`). The copy is deleted in `unwind-protect` and on load (stale copies).
- **mpv** never gets cookies. Emacs resolves the streams itself (§7.1a), and only yt-dlp sees cookies.

**Re-export after failure:**
- On an `expired` failure, the generation is checked first. If another request has already re-exported, the request simply retries. Otherwise a single-flight `(auth . export)` call runs, and waiting requests join it instead of being dropped. Each request is retried at most once.
- Re-export reads the same dedicated profile without prompting. If it still fails, the message is "Session expired — sign in to YouTube in Chromium profile ‘emacs-yt’, then `L`".

**Emacs-side hygiene:**
- Cookie text is only handled in a temp buffer with `buffer-undo-list t`, killed in `unwind-protect`. Only sanitized errors are signalled.
- `yt-state-directory` is added to `recentf-exclude`.
- Files under `yt-state-directory` get an `auto-mode-alist` entry that disables backups and auto-save.

**`yt-logout`** deletes the master file and the copies. Its message points out that this does **not** revoke the session; signing out in that Chromium profile does.

**Documented trade-off:** the cookies are Google-account session tokens (SID, SAPISID, `__Secure-3PSID`, …), not tokens limited to YouTube. The file is plaintext with mode 0600. The dedicated profile limits how much is exposed if the file leaks.

**Auth state:** `yt--auth-state` is one of unknown, ok, expired, keyring-error, no-cookies, rate-limited, or bot-check, plus a timestamp. It is shown in the feed's header line as a button that runs `yt-login`.

### 4.3 Invocations (everything before `--` comes after the base args)
| Purpose | Args |
|---|---|
| Subscriptions feed (NDJSON) | `--flat-playlist --lazy-playlist -I 1:N --extractor-args youtubetab:approximate_date -j -- :ytsubs` |
| Video info | `-J --no-playlist --ignore-no-formats-error -- URL` |
| Subscribed channels | `--flat-playlist -J -- https://www.youtube.com/feed/channels` |
| Channel uploads | `--flat-playlist --lazy-playlist -I 1:N -j -- https://www.youtube.com/channel/UC…/videos` |
| Search | `--flat-playlist -j -- "ytsearch20:QUERY"` |
| Stream resolve (mpv and VLC, §7.1a) | `--no-playlist -f FORMAT -j -- URL`. Use `requested_formats[].url`, `http_headers` and `available_at`. Not `--print urls` / `-g`: they lack `available_at`. |

- `:ytsubs` fails clearly when logged out. It only checks that the cookies are present, though, not whether the server still accepts them. A feed run that exits 0 with zero entries or with a "no longer valid" warning is therefore classified as `expired`.
- The second pass (exact date, description, chapters, tags) runs only from the info buffer, through a queue that allows 2 at once.

### 4.4 Incremental refresh
- Each NDJSON line is converted to a `yt-video` and collected.
- After `yt-feed-stop-after-known` consecutive ids that are already cached, `ON-LINE` returns `'stop`. The default is 10, and `nil` turns this off.
- Results are merged in a single `with-sqlite-transaction`: new entries go first, and `view_count` and `live_status` are updated (upcoming → live → was_live).
- **Caveat** (documented): premieres and live streams can reorder the feed, so an incremental refresh can miss items. `G` / `C-u g` cancels the current run and does a full refresh of up to `yt-feed-limit` (100) items. The first fetch of a session is always full.

### 4.5 Error classification (ordered `defconst` of regexps, first match wins, scanned on every exit)
| # | Regexp (case-insensitive) | Class | Action |
|---|---|---|---|
| 1 | `not a bot` | bot-check | Back off 15 min (`defvar`). Suggest opening YouTube in the profile. **No re-export.** |
| 2 | `confirm your age\|age-restricted` | age | Explain; cookies are needed at playback. |
| 3 | `members-only\|join this channel` | members | Explain. |
| 4 | `rate-limited\|HTTP Error 429\|try again later` | rate-limit | Back off 60 min. |
| 5 | `login details are needed\|no longer valid` (also: the feed exits 0 with zero entries; also `redirected to youtube.com home page`, **feed source only**) | expired | Re-export flow (§4.2). |
| 6 | `could not find chromium cookies database` | bad-profile | Re-run `yt-login`. |
| 7 | `failed to load cookies\|does not look like a Netscape format\|must be Netscape formatted`. yt-dlp wraps the parser's error in `CookieLoadError('failed to load cookies')` (`cookies.py:113`). | corrupt-cookies | Re-export. |
| 8 | `urlopen error\|name resolution\|timed out` | network | "Offline — showing cached feed". |
| 9 | `unable to extract\|unable to recognize tab page\|signature solving failed\|n challenge` | extractor | Version hint. |
| 10 | `requested format is not available` | format | Retry once with `b`. |
| — | exit 0 and no JSON (non-feed) | parse | Show an stderr excerpt. |
| — | make-process `file-missing` | missing | "yt-dlp not found (`yt-ytdlp-program`)". |

- The text "Use --cookies-from-browser or --cookies" is **not** a pattern. yt-dlp appends it to every sign-in reason, including the bot check.
- The bot-check regexp avoids the apostrophe, because YouTube sends a curly one.
- **Version check:** parse `yt-dlp --version` once per session and warn if it is older than `yt-ytdlp-min-version` or more than 60 days old. The hint text comes from `yt-ytdlp-update-hint`, which defaults to `"update yt-dlp (it comes from: %s)"` with `(executable-find yt-ytdlp-program)` filled in.

## 5. Cache (`yt-cache.el`)
- **Location:** `sqlite-open` on `yt-cache-file`, which defaults to `yt-state-directory/yt.sqlite`.
  - The parent directory is created first with mode 0700, and the file is set to 0600.
  - If `sqlite-available-p` is nil, the package signals a clear `user-error`. There is no in-memory fallback.
- **On open:**
  - `PRAGMA journal_mode=WAL; PRAGMA busy_timeout=3000;`
  - The schema is created with `IF NOT EXISTS` inside `BEGIN IMMEDIATE`, and `schema_version` is checked.
- **Tables:**
  - `videos(id PK, data TEXT, fetched_at INT, watched INT, position REAL, ts_exact INT)`. `data` holds an **allowlisted** set of struct fields. Raw yt-dlp JSON is never stored, because it would include signed googlevideo URLs that contain `ip=`.
  - `channels(id PK, data TEXT)`.
  - `meta(key PK, value)`.
- **API:**
  - `yt-cache-put-videos` upserts in one transaction and preserves watched and position.
  - `yt-cache-videos &optional LIMIT`, `yt-cache-get`, `yt-cache-set-position`.
  - `yt-cache-meta` / `yt-cache-set-meta`.
  - `yt-forget-history` clears watched and position.
- **Watched state:** `yt-mark-watched VIDEO-OR-ID &optional UNWATCHED` is the **only** way to change it. It writes the row and then runs `yt-watched-changed-functions` with the id.
- **Shutdown:** `kill-emacs-hook` closes the database at depth 90, so it runs after the player has finalized.

## 6. Feed UI (`yt-feed.el`, `yt-info.el`, `yt-select.el`)
**Widget: tabulated-list-mode, not vtable.**
- vtable measures every cell with `string-pixel-width`, which is slow at 500 rows.
- `vtable-update-object` signals an error when the buffer isn't visible, which is common after an async refresh.
- tabulated-list's `remember-pos` compares ids with `equal`, which works with video-id strings. It falls back to `point-min` when the id is gone, and it only moves the buffer's point, so per-window restore and "nearest row" are written by hand.

**Rows:** the row id is the video-id string. A buffer-local hash maps id to `yt-video`. `yt-feed-video-at-point` returns the struct at point.

**Buffers:**
- `*yt: Subscriptions*`, `*yt: <Channel>*`, `*yt: Channels*`, `*yt: Info*`.
- The buffer-local `yt-feed--source` is either `subscriptions` or `(:channel ID URL NAME)`. `revert-buffer-function` dispatches on it.
- `M-x yt` reuses an existing buffer without refetching if the last refresh was less than `yt-feed-refresh-interval` ago (15 min).

**Columns:**
| Column | Content |
|---|---|
| marker | `●` if unwatched |
| Age | `now`, `42m`, `3h`, `2d`, `3w`, `5mo`, `2y`, `in2h` |
| Dur | `12:34`, `1:02:03`, `LIVE`, `SOON` |
| Channel | 20 characters, may be empty for Shorts |
| Title | badge `[LIVE]` / `[SOON 18:00]` / `[S]` plus the title |
| Thumb | first column, only when thumbnails are on |

- Default sort is Age, newest first.
- Faces are `defface`s inheriting from standard faces: `yt-feed-age`, `-duration`, `-channel`, `-title`, `-title-unwatched`, `-title-watched`, `-live`, `-upcoming`, `-short`, `-new-marker`.

**Header line** (not the mode line): the auth state as a login button if not `ok`, "updated 5m ago", the active filter, and the visible count.
- `mode-line-process` shows " Refreshing…" only while a fetch is running.
- One **global** 5-minute timer re-prints the visible feed buffers that aren't currently refreshing, so the ages stay current.

**Keymaps.** `yt-video-actions-map` is shared: it is the parent of the feed, info, playlist, and embark maps. It composes with `tabulated-list-mode-map`, which keeps n/p, S, `{`/`}`, SPC/DEL, q, h/?, and digit arguments.

| `n` / `p` | next / previous |
| `l` | playlist |
| `S` | stop, keeping the playlist |
| `Q` | quit mpv |

`yt-player-map` holds the same player keys, bound under `P` in yt buffers.

**Refresh flow:**
1. `M-x yt` fills the buffer from the cache immediately.
2. If there is no master cookie file, it starts `yt-login` itself, showing body text "Signing in via Chromium profile …". Otherwise it fetches.
3. The callback returns early unless `buffer-live-p`.
4. Results are merged through the cache.
5. For every window showing the buffer, the code records the id at point and the line offset of `window-start`.
6. `tabulated-list-print t` redraws the buffer.
7. Each window's position is restored by searching for its id (nearest row if the id was filtered out).
8. Errors leave the cached rows in place and appear in the header line and as a message.

**Filtering:**
- The filter state is the plist `(:query :channel-id :hide-watched :hide-shorts :hide-upcoming)`, implemented as pure functions (`yt-feed--parse-query`, `yt-feed--match-p`) and applied in the entries function. Filtering never refetches.
- **Query syntax:** space-separated terms are ANDed over title and channel. `@foo` matches the channel only, `!foo` excludes.
- **Live filtering:** `minibuffer-with-setup-hook` adds an `after-change-functions` handler that is local to the minibuffer and debounced by 0.15 s.
  - The debounce timer is cancelled in `minibuffer-exit-hook`.
  - `C-g` restores the previous filter.

**Watched redraw:** `yt-watched-changed-functions` makes each live feed buffer find the row by id and re-print that one line inside `save-excursion`.

**Channels view:**
- Columns: Channel, Unwatched, Last upload.
- `RET` opens the channel's uploads in `yt-feed-mode`, `/` filters, `b` browses.

**Info buffer:**
- Shown immediately: title, channel (as a button), absolute and relative date, duration, live status, views, watched state, URL.
- Fetched asynchronously by the second pass: description (with goto-address), chapters as buttons that play from that time, tags, likes.
- `RET` runs `push-button` when point is on a button, and plays otherwise.

**Selection (`yt-select.el`):**
- `yt-select-video` is a completing-read with category `yt-video`. Its metadata sets an annotation-function (channel, age, duration), an optional group-function by channel, and `display-sort-function identity`.
- Candidates carry a text property, with a hash table as backup.
- **marginalia:** an entry is added to the annotator registry.
- **embark:** `yt-embark-video-map` has `yt-video-actions-map` and `embark-general-map` as parents. It is registered in `embark-keymap-alist`, and a target finder makes embark work in feed buffers.
- All of this is guarded with `with-eval-after-load`, and `defvar`s keep the byte-compiler quiet.

**Thumbnails** (`yt-feed-thumbnails`, nil by default, and only when `display-images-p`):
- Source: `https://i.ytimg.com/vi/ID/mqdefault.jpg`, cached under `(expand-file-name "yt/thumbs" (xdg-cache-home))`.
- Fetched with `curl -sf -o FILE.part` and then renamed. Fetches run in a queue of 4 and are deduplicated by id. There is **no url-retrieve fallback**, because that would send url.el's cookies and user agent.
- Visible rows come from the stubbable function `yt-feed--visible-ids`.
- When the file already exists, the image goes straight into the entry spec, so it survives re-prints. A finished download finds its row by id.

## 7. Playback (`yt-player.el`, `yt-mpv.el`, `yt-vlc.el`)
### 7.1 Interface
```elisp
(defcustom yt-player-backend 'auto :type '(choice (const auto) (const mpv) (const vlc) symbol))
(defcustom yt-player-format "bv*[height<=1080]+ba/b" :type 'string)
(cl-defgeneric yt-player-available-p (backend))
(cl-defgeneric yt-player-play (backend video &key start))
(cl-defgeneric yt-player-enqueue (backend video))
(cl-defgeneric yt-player-stop (backend))
(cl-defgeneric yt-player-command (backend cmd &rest args)) ; default: user-error "Not supported by %s"
```
- Methods use the quoted form `(eql 'mpv)`. A method that ignores `start` declares `&key ((:start _start))`.
- `auto` resolves to `mpv` if `(executable-find yt-mpv-program)` succeeds, otherwise to `vlc`.
- If mpv is requested but missing, the error says: "mpv not found — enable the yt flake's home-manager module (or `nix profile install ~/dev/emacs-yt#runtime`), or use `v` for VLC."

**Watched marking:**
- `yt-mark-watched-when` is `near-end` or `start`. mpv uses near-end with `yt-player-watched-threshold` 0.9. VLC always marks at start, and the README notes this difference.

**Resume** (`yt-player-resume`, default t):
- Skipped when the saved position is under 30 s or past the threshold.
- Otherwise the message is "Resuming at 12:34 — C-u RET plays from start".

### 7.1a Stream resolver (shared by mpv and VLC; changed by the M0 spike)
mpv's ytdl_hook **cannot play YouTube**. yt-dlp now gives each format an `available_at` time 3–5 s in the future, a fetch before that time gets HTTP 403, and ytdl_hook fetches immediately (docs/spike.md). Emacs therefore resolves every video itself:
- **`yt-ytdlp-resolve VIDEO FORMAT CALLBACK`** (in `yt-ytdlp.el`) runs `<base> --no-playlist -f FORMAT -j -- URL` through `yt-process-run`, with the usual per-run cookie copy and write-back (§4.2). It calls CALLBACK with the plist `(:video URL :audio URL-or-nil :headers ALIST :available-at EPOCH :title STR :duration N)`:
  - `requested_formats` gives the video and the audio entry; a single combined format gives only `:video`.
  - `:headers` comes from that format's `http_headers`.
  - `:available-at` is the maximum `available_at` over the formats, or nil.
- **Waiting:** `yt-player--when-available PLIST FN` calls FN from a `run-at-time` timer once `(yt--now)` has passed `:available-at` plus 1 s, so Emacs never blocks.
- **Benefits:**
  - The §4.5 classifier sees the full yt-dlp stderr for every playback. ytdl_hook used to hide it behind `--no-warnings`.
  - Playback uses the same per-run cookie copy and write-back as everything else.
  - mpv never needs cookies.
- **Expiry:** URLs expire after about 6 h. A queued mpv entry whose `end-file` reason is `error` is re-resolved and reloaded **once**.

### 7.2 mpv backend
One long-lived idle mpv per Emacs session. It is started lazily. `yt-mpv--instance` is incremented on every spawn, and every timer, filter, and sentinel checks it and does nothing if it has changed.

**Spawn:**
1. Take `WAYLAND_DISPLAY` from `(getenv "WAYLAND_DISPLAY" (selected-frame))`, or else the last value seen. Signal a `user-error` if it can't be found. This is needed because the daemon has no Wayland display.
2. Prepend it to `process-environment`.
3. Remove a stale socket at the path without following symlinks.
4. Run:
```
mpv --idle=yes --force-window=yes --no-terminal --ytdl=no
    --input-ipc-server=<yt-runtime-directory>/mpv-<emacs-pid>-<instance>.sock
    --wayland-app-id=emacs-yt
    --title=${media-title} — emacs-yt          ; argv element, no shell quotes
    <yt-mpv-extra-args, default ("--hwdec=auto-safe")>
```
- `--ytdl=no` turns off ytdl_hook. Every URL that mpv gets is a resolved stream URL from §7.1a.
- An empty window stays open after the playlist ends. This is documented, and `--keep-open=yes` is offered as an alternative.

**Connect:** `yt-mpv--connect SOCKET` is separate from spawning, so tests can call it directly.
- It makes up to 50 `make-network-process :family 'local :coding 'utf-8` attempts, 0.1 s apart, catching `file-error`.
- Commands sent before connecting queue in `yt-mpv--pending`. If every retry fails, the queue fails with an error and mpv is killed.
- On disconnect while the process is still alive, it reconnects up to 3 times with backoff. Each reconnect re-sends every `observe_property`.
- On every disconnect, each pending callback is called with `(:type disconnected)` and the callback table is cleared.

**Framing:**
- The filter collects partial lines in `yt-mpv--partial` and parses each complete line with `json-parse-string` (same keywords as §2, so `false` becomes `nil`).
- **Send:** positional commands are encoded as `{"command":[...],"request_id":N}` (`vconcat` only for positional lists). Named commands are encoded as `{"command":{"name":"loadfile",...},"request_id":N}`, with the plist passed through unchanged.
- **Key omission:** keys whose value is nil are left out, because `json-serialize` turns nil into `{}`.
- **Replies** are matched to their callback by `request_id`.
  - A reply whose `error` is not `"success"` is reported.
  - The exception is `playlist-next`/`playlist-prev` at either end of the playlist, which are ignored silently.

**On connect:**
- `["observe_property",<obs-id>,P]` for each of pause, time-pos, duration, media-title, playlist-pos, speed, idle-active. Events arrive as `{"event":"property-change","id":…,"name":P,"data":…}` and are dispatched **by `name`**. A missing `data` means nil, for example `duration` while idle.
- `["request_log_messages","warn"]`. Messages are kept in a ring of 20 for `yt-player-show-log` (for example ffmpeg's `HTTP error 403`). The level is never set to verbose or debug, because those levels log HTTP headers.

**Commands:**
| Action | JSON `command` |
|---|---|
| play now | `{"name":"loadfile","url":V,"flags":"replace","options":{"audio-file":A,"force-media-title":"T","user-agent":UA,"start":"123.4"}}`. Option values **must be strings** (verified: a number gives `invalid parameter`). `audio-file` is omitted for a combined format, and the other `:headers` go in `http-header-fields`. Sent from the §7.1a timer, after `available_at`. |
| enqueue | same with `"flags":"append-play"` |
| pause | `["cycle","pause"]` |
| seek | `["seek",±N,"relative"]` / `["seek",S,"absolute"]` |
| speed | `["multiply","speed",1.1]` / `["set_property","speed",1.0]` |
| next / prev | `["playlist-next","weak"]` / `["playlist-prev","weak"]` |
| playlist | `["get_property","playlist"]` (entries have `id`), `["playlist-play-index",i]`, `["playlist-remove",i]` |
| stop | `["stop","keep-playlist"]` |
| quit | `{"command":["quit"]}`. A bare `["quit"]` line is ignored by mpv (verified). |

- **M0 spike result:** the named `loadfile` form with an `options` map works on mpv 0.41. It returns `{"data":{"playlist_entry_id":N}}`, and it played a real video to `end-file reason=eof` on sway (docs/spike.md).

**Tracking (by `playlist_entry_id`):**
- The `loadfile` reply carries `data.playlist_entry_id`, and the callback stores `entry-id → yt-video`.
- `start-file` sets the current entry and resets max-time-pos and duration.
- `end-file` carries `reason`: eof, stop, quit, error, redirect, or unknown.
  - On `redirect`, nothing is finalized.
  - `file_error` is read only when the reason is `error`.

**Finalize (`yt-mpv--finalize ENTRY-ID`):** runs at most once per entry, triggered by end-file or by the process sentinel. It marks the video watched if the reason is eof or max-pos/duration is at least the threshold, but never when the reason is error. Otherwise it saves the position.

**Lifecycle:**
- **Process sentinel** (crash, closed window, or quit; the order is end-file `quit`, then `shutdown`, then exit):
  1. finalize the current entry,
  2. clear state and timers,
  3. delete the socket,
  4. show "mpv exited".
- **`kill-emacs-hook`:**
  1. finalize synchronously from the last known state,
  2. send `["quit"]`,
  3. call `accept-process-output` for about 0.3 s,
  4. delete the process and the socket.

**Now playing:** `yt-player-mode` turns on automatically at first play.
- It adds the symbol `yt-player--mode-line` (marked `risky-local-variable`) to `global-mode-string`.
- The segment reads `▶ Title(20) 12:34/45:00 ×1.25`, with `⏸` when paused, and is hidden when `idle-active` is true.
- It calls `force-mode-line-update t` only when `(floor time-pos)`, pause, or the title changes.
- The text comes from the pure function `yt-player--segment-string`, which is what tests exercise.

**Repeat:** for seek, pause, speed, and next/prev only, a `set-transient-map` loop lets you keep tapping the key, so it works without repeat-mode. `S` and `Q` never repeat. `yt-player-repeat-map` is also provided for repeat-mode users.

**Playlist buffer:** `*yt-playlist*` in tabulated-list, built from `get_property playlist`. `RET` plays the entry, `d` removes it, `g` refreshes. Its keymap's parent is `yt-video-actions-map`.

**sway:** the README gives a snippet in the dotfiles' `wmWindowRules` format: `{ sway.app_id = "^emacs-yt$"; command = "floating enable, sticky enable, resize set 960 540"; }`. The existing `^[Ee]macs$` rule won't match it.

**Dotfiles change (done 2026-10-31):** `services.emacs.startWithUserSession = "graphical";` is now set in `homeManager.waylandBase` (`~/dotfiles/nix/modules/programs/wayland-base.nix`), so it applies only to the sway and Hyprland hosts, and the daemon there inherits `WAYLAND_DISPLAY`. The i3, xfce and headless hosts keep `default.target`. Passing the frame's `WAYLAND_DISPLAY` through (above) stays as a fallback.

### 7.3 VLC backend
1. Resolve with `yt-ytdlp-resolve` (§7.1a). Not `--print urls`: it doesn't give `available_at`, and VLC would get 403.
2. Once `available_at` has passed, launch `vlc --no-video-title-show --play-and-exit --meta-title=TITLE --http-user-agent=UA V [--input-slave=A]`. All the flags were checked against the installed vlc. The WAYLAND_DISPLAY handling is the same as for mpv.

Notes:
- **Signed URLs:** the URLs are signed, tied to the IP address, and expire after about 6 h, so they are resolved right before launch and never cached.
- **A/V sync:** if A/V sync is bad, fall back to format `b`.
- **Fire-and-forget:**
  - `stop` kills the process.
  - `enqueue` and the other commands report "not supported".
  - The rc interface is out of scope.

### 7.4 Playback errors
The resolver's yt-dlp stderr goes through the §4.5 classifier for both backends. When mpv's `end-file` reason is `error`, the file is re-resolved once (§7.1a), and the mpv log ring is offered through `yt-player-show-log`.
- **Format error:** retry once with `b`.
- **Age, members-only, or bot check:** show the specific explanation.
- **Anything else:** show the last error line, and `M-x yt-player-show-log` opens the ring or stderr.

## 11. Build, lint, test, and the separate test Emacs
**Rule: tests never run in the host Emacs.**
- The Makefile defaults to `EMACS ?= $(YT_EMACS)`.
- It **aborts** if `$(EMACS)` isn't under `/nix/store` or `YT_EMACS` is unset, with the message "run inside `nix develop` or use `nix run .#test`".

**Isolated environment** (exported by the Makefile for every target):

- Every invocation is `$(EMACS) -Q --batch -L . -L test`.
- `test/yt-test-helpers.el`:
  - asserts **before any test runs** that `yt-state-directory`, `yt-cache-file`, and `yt-runtime-directory` are under that temp root;
  - stubs `customize-save-variable` to signal an error, as a guard.

**Make targets:**

|---|---|

**Sandbox Emacs (`nix run .#sandbox`)**, for manual and live testing: a wrapper script that starts `emacs-test` as a GUI process separate from the host daemon.
- Sets `XDG_STATE_HOME` and `XDG_CACHE_HOME` to `<repo>/.sandbox/{state,cache}`, and sets `yt-runtime-directory` to `$XDG_RUNTIME_DIR/yt-sandbox` (0700). `XDG_CONFIG_HOME` stays real, because yt-dlp finds the Chromium profile through it (docs/spike.md).
- Unsets `LD_LIBRARY_PATH`, as the dev shell also does. The host shell's value makes the flake's mpv fail with `GLIBC_2.43 not found` (docs/spike.md).
- Puts the flake's mpv, yt-dlp, vlc, `yt-export-cookies`, and curl first on PATH.
- Runs `emacs --init-directory=<repo>/.sandbox/emacs.d --name yt-sandbox`. That init directory holds a generated `init.el` that only adds the repo to `load-path`, `(require 'yt)`, and binds `C-c y`.
- **Effect:**
  - Its own cookie export, from the dedicated profile, into `.sandbox/state`.
  - Its own SQLite file and its own mpv socket names.
  - Code changes take effect with `M-x eval-buffer` or a restart, with no straight rebuild.
- `make test-live` / `M-x yt-run-live-tests` inside the sandbox runs `test/yt-live-tests.el`: 3 real feed items, resolving one stream, playing 5 s in mpv. These tests always `(skip-unless (getenv "YT_LIVE"))`.

**Test design** (the default run uses no network, no mpv, no vlc, and no real cookies):
- **Waiting:** `yt-test-wait-until PRED` polls with `(accept-process-output nil 0.05)`. The cap defaults to 30 s and can be overridden by environment variable. On timeout it fails with the predicate's name.
- **`test/bin/fake-yt-dlp`** is a `#!/bin/sh` script with mode 755.
  - It is located with `(expand-file-name "bin/fake-yt-dlp" yt-test-dir)` and bound to `yt-ytdlp-program`.
  - `FAKE_SCENARIO=dir` keeps a call counter and replays `NN.out`, `NN.err`, and `NN.exit` for each call. This covers probe sequences, re-export and retry, and format retry.
  - It appends its argv to `dir/argv.log`, so tests can assert that `--ignore-config` is present, the denylisted flags are absent, `--` comes before the URL, and the `--cookies` path is the per-run copy.
  - Modes: stream (partial lines, `sleep 0.05`) and hang (`exec sleep 1000`, so SIGINT reaches it).
- **`test/bin/fake-export-cookies`** emits the JSON summary and writes a hand-made cookies.txt.
- **Direct filter tests** (NDJSON and mpv) feed in chunks that:
  - split a line in the middle, or merge several lines into one chunk;
  - are empty;
  - **split a multibyte UTF-8 title in the middle of a character**;
  - leave a trailing partial line at exit;
  - contain later lines after a `'stop` in the same chunk, which must be suppressed.

  Also tested: success after a self-requested SIGINT, and the single-flight and forced-restart paths.
- **Classifier:** a table-driven test with one real `err-*.txt` fixture per class, each tagged with the yt-dlp version it came from. It covers precedence (the bot-check message also contains the cookie hint, and "timed out" appears inside other messages), warning-only exit-0 output (which must not count as an error), and empty stderr.
- **Auth:**
  - the domain filter with a hostile fixture (`notyoutube.com`, malformed lines);
  - modes are 0600 for files and 0700 for directories;
  - per-run copy and write-back with a generation check;
  - concurrent re-export joins the running one;
  - profile parsing from a fixture `Local State`.
- **mpv IPC:**
  - The fake server is `make-network-process :server t`, with its socket from `make-temp-file` in `temporary-file-directory`, falling back to `/tmp` if the path would be longer than 100 characters.
  - A `sleep 1000` child stands in for the mpv process (via the `yt-mpv--process-alive-p` seam).
  - `unwind-protect` cleans up the server, the clients, and the socket.
  - Covered: the pending queue, request_id callbacks and error replies, a server-side disconnect followed by reconnect and re-observe, the instance guard, stale-socket removal, finalize being idempotent for eof, error, and threshold, resume, and tracking by entry-id with a duplicate URL.
  - The argv builder is tested as a pure function.
- **Feed:**
  - rendering from fixtures, sort order, and timestamp inheritance for Shorts;

## 13. Privacy notes (README)
- **Network contacts:**
  - yt-dlp talks only to www.youtube.com: the page, `youtubei/v1/browse` continuations, and the player JS, which deno runs locally.
  - The googlevideo CDN is contacted during playback.
  - Thumbnails come from i.ytimg.com with no cookies, using curl only.
- **No telemetry**, and no yt-dlp self-update (Nix pins it).
- **Cookies:**
  - They come only from the dedicated `emacs-yt` profile and only for youtube.com, in a 0600 plaintext file under `~/.local/state/yt/`.
  - They are Google-account session tokens.
  - They are never logged.
  - `yt-logout` deletes the files. Signing out of the profile revokes the session.
- **Local data:**
  - Watch history lives in a 0600 SQLite file, cleared with `yt-forget-history`.
  - Search queries appear in `/proc/*/cmdline` while yt-dlp runs (no hidepid), and are redacted in `*yt-log*`.
- **mpv socket:** it sits in `$XDG_RUNTIME_DIR/yt/` with mode 0700. mpv IPC can run arbitrary commands, so a world-writable fallback is never used.
