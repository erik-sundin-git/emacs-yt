#+title: yt: YouTube subscriptions in Emacs

yt shows the subscription feed of your YouTube account in an Emacs buffer,
and plays videos in an mpv window controlled from Emacs, or streams them to
VLC.  It signs in with cookies from a Chromium profile used only for it,
and fetches everything with yt-dlp.  It uses no OAuth and no API key.

Needs: Emacs 30, yt-dlp with a JavaScript runtime, mpv (or VLC), Chromium,
Python 3.  Linux only.

- =M-x yt= opens the subscription feed: the cached videos at once, then a
  refresh in the background.
- =RET= plays a video in mpv, which Emacs controls: pause, seek, speed, a
  queue, the video playing in the mode line, resuming where you stopped,
  and skipping sponsored segments with [[https://sponsor.ajay.app][SponsorBlock]].  =v= streams it to
  VLC instead.
- Channels and their uploads and playlists, subscribing, saved playlists,
  search, video details with chapters, watched marks, filters and
  thumbnails; completion and embark actions; YouTube links and org links
  that play in yt; player keys for your window manager.

* Requirements
- Emacs 30.1 or later, built with SQLite support.
- yt-dlp, kept recent: YouTube changes often.  It needs a JavaScript
  runtime to run YouTube's player script, by default deno; the nixpkgs
  yt-dlp brings its own.
- mpv, VLC, or both.  mpv is the one Emacs controls; VLC only plays.
- Chromium or ungoogled Chromium (not Chrome, Brave or Firefox), with a
  profile used only for YouTube.  Its cookies are decrypted with the GNOME
  keyring (Secret Service), or need none; KWallet is not supported.
- Python 3 with the =yt-dlp= and =secretstorage= modules, for the cookie
  exporter.
- curl, for thumbnails, subscribing and SponsorBlock.
- Linux.  Tested on NixOS with sway (Wayland); other distributions should
  work.

* Installation
** With package-vc
#+begin_src emacs-lisp
(package-vc-install '(yt :url "https://github.com/erik-sundin-git/emacs-yt"))
(keymap-global-set "C-c y" yt-map)
#+end_src

** With straight.el
#+begin_src emacs-lisp
(use-package yt
  :straight (yt :host github :repo "erik-sundin-git/emacs-yt" :files ("*.el"))
  :bind-keymap ("C-c y" . yt-map))
#+end_src

** From a checkout
#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/emacs-yt")
(require 'yt)
(keymap-global-set "C-c y" yt-map)
#+end_src

** The helper programs
yt runs two small programs from the checkout's =bin/= directory:

- =yt-export-cookies= exports the youtube.com cookies of the Chromium
  profile.  yt cannot sign in without it.  Without Nix, put a wrapper on
  =PATH= (or set =yt-export-cookies-program= to its file name):
  #+begin_src sh
  printf '#!/bin/sh\nexec python3 /path/to/emacs-yt/bin/yt-export-cookies.py "$@"\n' \
    > ~/.local/bin/yt-export-cookies
  chmod +x ~/.local/bin/yt-export-cookies
  #+end_src
- =yt-remote= runs player commands from outside Emacs (see [[*Player keys outside Emacs][Player keys
  outside Emacs]]); it is optional.  Copy =bin/yt-remote= onto =PATH= and
  make it executable.  It needs =emacsclient= and =notify-send=.

** With Nix and Home Manager
The flake provides a Home Manager module, which installs mpv and both
helper programs:

#+begin_src nix
# flake.nix inputs
emacs-yt = {
  url = "github:erik-sundin-git/emacs-yt";
  inputs.nixpkgs.follows = "nixpkgs";
};

# in the Home Manager configuration
imports = [ inputs.emacs-yt.homeModules.default ];
programs.yt.enable = true;        # mpv, yt-export-cookies, yt-remote
programs.yt.installElisp = true;  # yt in programs.emacs.extraPackages
programs.yt.mpris = true;         # optional: media keys control mpv
#+end_src

The module does not install yt-dlp or VLC.  It does not set
=nixpkgs.overlays=, so it works with =useGlobalPkgs=.  Alternatively,
=overlays.default= adds =yt= to every Emacs package set (=emacs.pkgs.yt=),
plus =yt-el=, =yt-export-cookies=, =yt-remote= and =yt-runtime= (mpv and
the exporter).

* Setup
1. In Chromium, create a new profile, for example named =emacs-yt=, and
   sign in to YouTube there, and nowhere else.  The cookies yt reads are
   Google session tokens: a profile used only for this keeps your main
   Google session out of reach.
2. Run =M-x yt-login=, or just =M-x yt=.  Choose the profile: yt preselects
   one named =emacs-yt=, and asks before using =Default=.  It exports only
   the youtube.com cookies and checks that they work.
3. =M-x yt= shows the subscription feed; =RET= on a video plays it.

If signing in fails, run =M-x yt-doctor=: it names the program, profile or
keyring that is missing.  =C-u M-x yt-login= chooses another profile.  See
also [[*Troubleshooting][Troubleshooting]].

** The mpv window
mpv opens its own window, with the Wayland app id =emacs-yt=, so window
managers can place it.  For example, in sway:

#+begin_src conf
for_window [app_id="^emacs-yt$"] floating enable, sticky enable, resize set 960 540
#+end_src

With the Home Manager module, =programs.yt.swayWindowRule = true;= adds
that rule, and =programs.yt.swayWindowCommand= changes its command.

When the queue ends, mpv stays open with an empty window, ready for the
next video; add =--keep-open=yes= to =yt-mpv-extra-args= to keep the last
frame instead.  =C-c y Q= closes it.  From an Emacs daemon, mpv and VLC
open on the display of the selected frame.

* Usage
The everyday keys, with =C-c y= as the prefix:

- Play the video at point: =RET=; from the start: =C-u RET=.  yt resumes
  where you stopped by itself.
- Add it to the queue: =a=; see the queue: =C-c y l=.
- Mark it watched or not watched: =w= / =u=.  Watched videos are hidden;
  =t w= shows them.
- Search YouTube: =C-c y s=.  Subscribe to the video's channel: =+=.
- Your channels: =C-c y c=.  What you played: =C-c y h=.
- Pause, from any buffer: =C-c y SPC=; seek: =C-c y <right>=.

Some terms: the *queue* is the list of videos mpv plays next.  A
*playlist* is a YouTube playlist; the ones you save stay in yt, not in your
YouTube account.  A *video list* is any buffer of videos: the
subscription feed, a channel's uploads, a playlist or search results.  The
*channel at hand* is the channel of the video at point, or the channel
whose uploads the buffer shows.

** Keys under C-c y
=C-c y= is the suggested binding for =yt-map=.  With which-key, it shows a
short label for each key.

| Key            | Opens                                         |
|----------------+-----------------------------------------------|
| =y= or =RET=   | the subscription feed, yt's main view         |
| =c=            | the channels you subscribe to                 |
| =P=            | the playlists you saved                       |
| =h=            | the videos you played (history)               |
| =s=            | a YouTube search                              |
| =f=            | a feed video chosen with completion, to play  |
| =u=            | a YouTube URL, to play                        |
| =L= / =d=      | sign in / diagnostics                         |

| Key                  | Player command                                  |
|----------------------+-------------------------------------------------|
| =SPC=                | pause                                           |
| =<left>= / =<right>= | seek 5 s (a prefix argument sets the seconds)   |
| =<down>= / =<up>=    | seek 60 s                                       |
| =[= / =]= / ~=~      | slower / faster / normal speed                  |
| =n= / =p=            | next / previous in the queue                    |
| =.= / =,=            | next / previous chapter                         |
| =l= / =z=            | the queue / shuffle it                          |
| =U= / =K=            | undo the last SponsorBlock skip / skipping on or off |
| =M=                  | switch the video playing to audio only, or back |
| =S= / =Q=            | stop / quit mpv                                 |
| =!=                  | the log of playback problems                    |

The keys for pausing, seeking, speed, next and previous, and chapters
repeat without the prefix: =C-c y <right> <right> <right>=.  The mode line
shows the video playing, its position, the chapter, the place in the queue
(=[2/5]=), ♪ for audio only, LIVE, and =skip:off= while SponsorBlock
skipping is off.  =M-x yt= and =M-x yt-subscriptions= also open the
subscription feed.

** Keys in video lists
These keys work in every video list; the video keys also work in the
details and queue buffers.

| Key             | Video at point (or the region)                      |
|-----------------+-----------------------------------------------------|
| =RET=           | play (mpv if installed, else VLC); =C-u RET= from the start |
| =v= / =m= / =M= | play in VLC / in mpv / audio only, in mpv           |
| =a=             | add to the queue                                    |
| =i=             | details: description, chapters (play from there), tags |
| =w= / =u=       | mark watched / not watched                          |
| =o= / =O=       | the uploads / the playlists of its channel          |
| =b= / =y= / =Y= | open in a browser / copy the URL / copy "Title — URL" |

| Key                 | Filter                                            |
|---------------------+---------------------------------------------------|
| =/=                 | words, =@channel=, =!exclude=                     |
| =c= / =C=           | show one channel / clear the filters              |
| =t w=               | show or hide watched videos (hidden by default)   |
| =t s= / =t u=       | hide Shorts / upcoming and live streams           |
| =t n=               | show only the videos new since your last visit (◆) |
| =t m=               | show the videos of muted channels                 |
| =t i=               | thumbnails                                        |

| Key           | List                                                  |
|---------------+-------------------------------------------------------|
| =g= / =G=     | refresh / cancel and fetch everything again           |
| =z=           | play the videos shown in random order                 |
| =A=           | play the unwatched videos shown from point down       |
| =W=           | mark every video shown as watched (=u= right after undoes it) |
| =+= / =-=     | subscribe to / unsubscribe from the channel at hand; in a playlist, save it / forget it |
| =x=           | mute or unmute the channel at hand                    |
| =T=           | in a channel: its past live streams, or its videos again |
| =S=           | sort by the column at point                           |
| =l= / =L=     | the channels / sign in                                |
| =P= / =j=     | the player keys / the keys of =C-c y=                 |

In the subscription feed, ● marks a video you have not watched, and ◆ one
that arrived since your last visit (when you last opened the feed, at least
ten minutes earlier); the header line counts them.

** Other lists
| List                   | Keys                                                  |
|------------------------+-------------------------------------------------------|
| Channels (=C-c y c=)   | =RET= or =o= uploads, =O= playlists, =b= browser, =x= mute, =-= or =d= unsubscribe |
| Playlists (=C-c y P=, =O=) | =RET= or =o= open, =z= shuffle, =+= save, =-= or =d= forget, =b= browser |
| History (=C-c y h=)    | the video keys, =d= remove, =D= clear                 |
| Queue (=C-c y l=)      | the video keys, =RET= play this entry, =d= remove, =z= shuffle |

Every list has =g= to refresh, =P= for the player keys and =j= for the keys
of =C-c y=.  All but the queue have =/= to filter (=C= clears it) and =L=
to sign in.

** Channels, subscribing and muting
The header line of a channel's uploads says whether you subscribe to it.
Unsubscribing asks first, and removes the channel's videos from the
subscription feed.  If YouTube refuses the request, yt offers to open the
channel in its Chromium profile, to click Subscribe there.

=x= mutes a channel: its videos leave the subscription feed, but its own
uploads still show everything, and the channels list marks it.  =t m=
shows the muted channels' videos in the feed, and =x= again unmutes.  Shorts name
no channel, so muting cannot hide them; =t s= does.

** Playlists and shuffling
A channel's playlists (=O=) and the saved ones (=C-c y P=) open in playlist
order, and show how many of their videos you have not watched.  Shuffling
queues one video at a time, plus two ahead; yt fetches the next as each
starts, so a long playlist does not send YouTube a request per video at
once.  =n= skips ahead; playing anything else ends the shuffle.

** History
=C-c y h= lists the videos you played in yt, the most recently played
first, with how long ago you played them and how far you got: where you
stopped, or "watched".  =RET= plays a video again, from where you stopped.
Removing a video from the history keeps its watched mark and resume
position.

The history stays in yt's cache.  With =yt-player-youtube-history= set, yt
also adds each video you play to your YouTube history, as yt-dlp's
=--mark-watched= does, so it shows on your other devices.  YouTube then
counts the video as watched to the end, and uses it for recommendations.
yt sends each video at most once per session; problems go to =C-c y !=.

** SponsorBlock
mpv skips the segments of videos that SponsorBlock's community marked as
sponsors, self-promotion or reminders to subscribe, and says so in the echo
area: "Skipped sponsor (44 s)".  =C-c y U= goes back to the start of the
segment skipped last, which is then not skipped again; =C-c y K= turns
skipping off or on for the session.  The details buffer (=i=) lists a
video's segments, and which of them mpv skips.

=yt-sponsorblock-categories= chooses the categories; intros, endcards,
recaps, filler and others are off by default, and nil turns SponsorBlock
off.  yt asks SponsorBlock while it fetches the video's streams, so
playback does not wait for it; when SponsorBlock cannot be reached, the
video plays without skipping.  VLC skips nothing: Emacs does not control
it.

** Completion and embark
=C-c y f= chooses a feed video with completion.  With embark, =embark-act=
on a video (a completion candidate or the row at point) offers the video
keys.  With marginalia, completion candidates show their channel, age and
duration.

* Integration
** YouTube links elsewhere in Emacs
With =(yt-url-handler-mode 1)= in your init file, =browse-url= opens
YouTube links in yt: a video plays in mpv, from the link's =t== time if it
has one, and a playlist or channel opens in a yt buffer.  That covers links
in mail (notmuch, gnus), org, help and most other buffers; eww passes only
the links matching =eww-use-browse-url= to =browse-url=.  With a prefix
argument, or when yt cannot open a link, the browser gets it as before.
yt's own "open in browser" commands (=b=) never go through the handler.
=yt-play-url= also starts at a link's =t== time.

Links come from text you did not write, so yt accepts only the YouTube
hosts, rebuilds a clean URL from the video, playlist or channel id
(dropping tracking parameters such as =si==), and never hands the link
itself to yt-dlp.

** Org links
With

#+begin_src emacs-lisp
(with-eval-after-load 'ol (require 'yt-org))
#+end_src

=org-store-link= (=C-c l=) in a yt buffer stores a link to the video at
point, described as "Title — Channel"; if that video is playing, the link
starts where it is (=&t=N=).  =C-c C-l= in a note inserts it.  The link is
a plain YouTube URL, so notes do not depend on yt, and with
=yt-url-handler-mode= on, following it plays the video in yt from that
time.

** Player keys outside Emacs
=yt-remote ACTION= runs a player command in the running Emacs, through
=emacsclient=, so window manager keys work wherever the focus is:
=yt-remote pause= pauses whatever yt plays.  The actions are:

- =pause=, =stop=, =quit=
- =seek-forward=, =seek-backward= (5 s), =seek-forward-more=,
  =seek-backward-more= (1 min)
- =next=, =previous=, =next-chapter=, =previous-chapter=
- =faster=, =slower=, =normal-speed=
- =unskip=, =toggle-skipping=, =toggle-audio=

What yt says back, such as "Nothing is playing", shows as a desktop
notification.  Most actions say nothing, since mpv answers later.  Emacs
must run a server (the daemon, or =M-x server-start=); =yt-remote= never
starts one.  A sway mode, for example:

#+begin_src conf
bindsym $mod+y mode yt
mode yt {
    bindsym --no-repeat k exec yt-remote pause
    bindsym l exec yt-remote seek-forward
    bindsym h exec yt-remote seek-backward
    bindsym --no-repeat n exec yt-remote next
    bindsym Escape mode default
}
#+end_src

MPRIS is the desktop's protocol for media players: media keys
(=playerctl play-pause=) and status bars use it.  With
=programs.yt.mpris = true;= in the Home Manager module, mpv gets its MPRIS
script, patched not to publish stream URLs, and yt follows what MPRIS
clients do.  Without Nix, install mpv's =mpris= script yourself, but note
that the stock script publishes the stream URL (see [[*Privacy][Privacy]]).  An MPRIS
"Stop" empties mpv's queue, unlike yt's own stop.  The option adds to
=programs.mpv.scripts=, which Home Manager does not allow with a custom
=programs.mpv.package=.

* Customization
=M-x customize-group RET yt= lists every option.  The most useful:

- =yt-player-backend=: =auto= (mpv if installed), =mpv= or =vlc=
- =yt-player-format=: the yt-dlp format, by default up to 1080p
- =yt-mark-watched-when=, =yt-player-watched-threshold=: when mpv counts a
  video as watched (by default after 90%)
- =yt-player-resume=: resume where you stopped
- =yt-feed-limit=, =yt-feed-refresh-interval=: how much to fetch, how often
- =yt-feed-hide-watched= (on by default), =yt-feed-hide-shorts=,
  =yt-feed-hide-upcoming=, =yt-feed-thumbnails=: the feed's defaults
- =yt-thumbs-height=: the height of thumbnails, by default 90 pixels
- =yt-sponsorblock-categories=: the SponsorBlock segments mpv skips
- =yt-save-minibuffer-history=: let =savehist-mode= keep what you type at
  yt's prompts
- =yt-player-youtube-history=: add the videos you play to your YouTube
  history
- =yt-cookie-profile=: the Chromium profile, instead of choosing it with
  =yt-login=

* Privacy
- *Network:* there is no telemetry and no self-update.  yt talks to:
  - www.youtube.com, through yt-dlp: pages, the API the pages use, and the
    player script, which its JavaScript runtime runs locally.  Subscribing
    and unsubscribing send one request each, through curl, with the
    cookies.  With =yt-player-youtube-history= set, yt-dlp tells YouTube,
    with the cookies, each time a video starts (once per session);
    YouTube counts it as fully watched, and =yt-forget-history= does not
    remove it there.
  - googlevideo.com: the players fetch the video streams.
  - i.ytimg.com: thumbnails, through curl, without cookies.
  - sponsor.ajay.app: before mpv plays a video, and when you open its
    details, curl asks for SponsorBlock segments, without cookies.  The
    request names only the first 4 characters of the SHA-256 hash of the
    video id, which many videos share.
- *Cookies:* only those of the chosen profile, only for youtube.com, in a
  mode 0600 file (and its previous version, =.prev=) under
  =~/.local/state/yt/=.  The exporter asks the GNOME keyring for Chromium's
  cookie key.  Every yt-dlp run gets its own private copy in
  =$XDG_RUNTIME_DIR/yt/=, deleted afterwards.  curl gets the same private
  copy when it subscribes; the request headers go in a mode 0600 config
  file, so nothing derived from the cookies shows in the process list.
  Cookie values are never logged or shown.  =M-x yt-logout= deletes the
  files; signing out of YouTube in the profile ends the session itself.
- *Local data:* a mode 0600 SQLite file next to the cookies holds the
  videos you played, watched marks and resume positions, and also your
  subscriptions, cached feeds, saved playlists and muted channels.  Only a
  fixed set of video fields is stored, never yt-dlp's raw output, which
  holds stream URLs signed for your IP address; those are kept in memory
  only, for mpv, until shortly before they expire, and forgotten on
  =yt-logout=.  =M-x yt-forget-history= forgets the played videos, watched
  marks and positions in that file.  It does not touch:
  - the backups yt keeps next to it, before a change of its format and on
    =M-x yt-cache-backup=: up to three =yt.sqlite.backup-…= files, mode
    0600;
  - a damaged cache that yt set aside, =yt.sqlite.damaged-…=, mode 0600;
  - the thumbnail cache in =~/.cache/yt/thumbs/=, named by video id.
  Delete those yourself to forget everything.
- *Logs:* =*yt-log*= lists the commands yt runs and how long playing took,
  by video id, with search queries replaced by =REDACTED=, stream URLs by
  =<stream URL>= and authorization headers and cookies by =<redacted>=.
  While a search runs, its query is visible to other local users in the
  process list.  =yt-doctor= shows no cookies, tokens or titles, but its
  file names show your user name.
- *Prompts:* searches, filters and URLs typed at yt's prompts have their
  own histories, which =savehist-mode= does not save unless
  =yt-save-minibuffer-history= is set.
- *mpv:* its control socket, which accepts any mpv command, is in the mode
  0700 runtime directory; yt never falls back to a shared directory.  With
  =programs.yt.mpris=, mpv publishes the title, position and length of the
  video playing on the session D-Bus, for every program of your session,
  which can also control it.  yt's copy of the MPRIS script leaves out the
  stream URL; other mpv scripts you install still see it, since yt's mpv
  loads your mpv configuration.
- *yt-remote:* it talks only to the Emacs server, and never starts one.
  yt's replies, which can name the video, show as desktop notifications,
  which your notification daemon may keep in its history.

* Troubleshooting
- *Signing in fails:* =M-x yt-doctor= shows what yt found: programs and
  versions, the display, directories, the cache and the sign-in state.
  =C-u M-x yt-login= chooses another Chromium profile.
- *The session expired:* yt exports the cookies again by itself, once.  If
  that does not help, sign in to YouTube in the profile again, then run
  =M-x yt-login=.
- *YouTube asks you to confirm you are not a bot:* yt pauses its requests
  for 15 minutes, and the header line says until when.  Open YouTube in the
  profile, then run =M-x yt-login= to end the pause.
- *Fetching or playing suddenly fails:* update yt-dlp, which has to keep up
  with YouTube; =yt-doctor= says when it is old.  "n challenge solving
  failed" means yt-dlp found no JavaScript runtime.
- *A video does not play:* =C-c y != shows the log of playback problems.

* Known limitations
- The subscription feed has no exact upload times, only YouTube's "3 hours
  ago", so ages are approximate until you open a video's details.  The
  order is YouTube's.  Shorts have no channel or time of their own.
- A refresh stops after 10 videos it already knows; premieres and streams
  that YouTube moves in the feed can be missed until =G=.
- VLC is not controlled: it marks a video as watched when it starts, and
  cannot queue.
- mpv starts a few seconds after =RET=: yt fetches the streams first, and
  YouTube releases them only some seconds after yt-dlp asks.  yt keeps the
  streams in memory, so playing or resuming a video again within a few
  hours starts at once.
- Stream URLs expire after some hours; a queued video that fails is fetched
  again, once.
- Subscribing sends the same request as the website's Subscribe button, to
  an API that is not documented.  If YouTube changes it, subscribe in the
  Chromium profile instead.
