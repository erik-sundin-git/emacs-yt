#+title: yt: YouTube subscriptions in Emacs

yt shows the subscription feed of your YouTube account in an Emacs buffer,
and plays videos in an mpv window controlled from Emacs or streams them to
VLC.  It signs in with cookies from a Chromium profile dedicated to it and
fetches everything with yt-dlp.  It uses no OAuth and no API key.

- =M-x yt= opens the subscription feed: the cached videos at once, then a
  refresh in the background.
- =RET= plays in mpv, which Emacs controls (pause, seek, speed, queue,
  now-playing in the mode line, resume where you stopped, skipping
  sponsored segments with SponsorBlock).  =v= streams to
  VLC instead.
- Channels, channel uploads, subscribing and unsubscribing, the playlists a
  channel made (and saving them in yt), search, video details with chapters, watched marks, filters,
  thumbnails, completion and embark actions.

* Requirements
- Emacs 30.1 or later, built with SQLite support
- yt-dlp (recent: YouTube changes often), with a JavaScript runtime such as
  deno (the nixpkgs package bundles one)
- mpv, VLC, or both; curl for thumbnails
- ungoogled Chromium or Chromium, with a profile used only for YouTube
- Linux; tested on NixOS with sway (Wayland)

* Installation
** With Nix and Home Manager
The flake provides a Home Manager module.  Add the flake as an input, import
the module and enable it:

#+begin_src nix
# flake.nix inputs
emacs-yt = {
  url = "git+file:///home/you/dev/emacs-yt";   # or a remote URL
  inputs.nixpkgs.follows = "nixpkgs";
};

# in the Home Manager configuration
imports = [ inputs.emacs-yt.homeModules.default ];
programs.yt.enable = true;        # mpv and yt-export-cookies
programs.yt.installElisp = true;  # yt in programs.emacs.extraPackages
programs.yt.swayWindowRule = true;  # optional: float mpv's window in sway
#+end_src

The module does not set =nixpkgs.overlays=, so it works with
=useGlobalPkgs=.  It does not install yt-dlp or VLC.  Alternatively,
=overlays.default= adds =yt= to every Emacs package set
(=emacs.pkgs.yt=), plus =yt-export-cookies= and =yt-runtime= (mpv and the
exporter); =nix build= builds the package itself.

** From the checkout, with straight.el
#+begin_src elisp
(use-package yt
  :straight (yt :type nil :local-repo "~/dev/emacs-yt" :files ("*.el"))
  :commands (yt yt-login yt-play-url)
  :bind-keymap ("C-c y" . yt-map))
#+end_src

The cookie exporter, =yt-export-cookies=, then comes from
=nix profile install ~/dev/emacs-yt#runtime= (with mpv), or set
=yt-export-cookies-program=.  After changing the code, run
=M-x straight-rebuild-package=.

* Setup
1. In Chromium, create a new profile, for example named =emacs-yt=, and
   sign in to YouTube there, and nowhere else.  The cookies yt reads are
   Google session tokens: a profile used only for this keeps your main
   Google session out of reach.
2. Run =M-x yt-login= (or just =M-x yt=).  Choose the profile; yt
   preselects one named =emacs-yt= and asks for confirmation before using
   =Default=.  It exports only the youtube.com cookies and checks that they
   work.
3. =M-x yt-doctor= shows what yt found: programs and versions, the
   display, directories, the cache, and the sign-in state.

When the session expires, yt exports the cookies again by itself, once.  If
YouTube asks to confirm you are not a bot, open YouTube in the profile, then
try again.  yt pauses its requests for 15 minutes, and the feed's header line
says until when; =M-x yt-login= (or =yt-check-auth=) ends the pause as soon as
YouTube accepts the session again.

* Keys
=C-c y= is the suggested binding for =yt-map=:

| Key            | Command                                      |
|----------------+----------------------------------------------|
| =y= or =RET=   | the subscription feed, yt's main view        |
| =c=            | the channels you subscribe to                |
| =P=            | the playlists you saved                      |
| =h=            | the videos you played (history)              |
| =s=            | search YouTube                               |
| =f=            | choose a feed video with completion, play it |
| =u=            | play a YouTube URL                           |
| =L= / =d=      | sign in / diagnostics                        |
| =SPC=          | pause                                        |
| =<left>= / =<right>= | seek 5 s (a prefix argument sets the seconds) |
| =<down>= / =<up>=    | seek 60 s                              |
| =[= / =]= / ===  | slower / faster / normal speed             |
| =n= / =p=      | next / previous in the queue                 |
| =.= / =,=      | next / previous chapter                      |
| =l=            | the queue: the videos in mpv's playlist      |
| =z=            | shuffle the queue                            |
| =U= / =K=      | undo the last SponsorBlock skip / skipping on or off |
| =S= / =Q=      | stop / quit mpv                              |
| =!=            | log of playback problems                     |

The player keys repeat without the prefix: =C-c y <right> <right> <right>=.
With which-key, =C-c y= shows a short label for each key.
=M-x yt= and =M-x yt-subscriptions= also open the subscription feed.

In the feed, channel uploads and search results (and, for the video keys,
the info and queue buffers):

| Key           | Command                                                  |
|---------------+----------------------------------------------------------|
| =RET=         | play (mpv if installed, else VLC); =C-u RET= from the start |
| =v= / =m=     | play in VLC / mpv                                        |
| =a=           | add to the queue (on the region too)                     |
| =i=           | details: description, chapters (play from there), tags  |
| =o=           | the uploads of the video's channel                       |
| =O=           | the playlists the video's channel made                   |
| =w= / =u=     | mark watched / not watched (on the region too)           |
| =b= / =y= / =Y= | open in a browser / copy the URL / copy "Title — URL"  |
| =P=           | the player keys above                                    |
| =g= / =G=     | refresh / cancel and refetch everything                  |
| =/=           | filter: words, =@channel=, =!exclude= (=s= too, until 0.4) |
| =c= / =C=     | show one channel / clear the filters                     |
| =t w=, =t s=, =t u= | hide watched videos, Shorts, upcoming streams      |
| =t n=         | show only the videos new since your last visit (◆)      |
| =W=           | mark every video shown as watched (=u= right after undoes it) |
| =t i=         | thumbnails                                               |
| =l=           | the channels                                             |
| =+= / =-=     | subscribe to / unsubscribe from the channel at hand; in a playlist: save it in yt / forget it |
| =z=           | play the videos shown in random order, in mpv            |
| =A=           | play the unwatched videos shown from point down, in order |
| =L=           | sign in                                                  |
| =j=           | every key of =C-c y=: =j c= channels, =j h= history, …   |
| =S=           | sort by the column at point (tabulated-list)             |

Every yt list has =j= for the keys of =C-c y=, =P= for the player keys,
=/= to filter (=C= clears it), =g= to refresh and =L= to sign in.

In the channels list, =RET= or =o= shows a channel's uploads, =O= its
playlists, and =-= or =d= unsubscribes from it.
A channel's playlists, and the saved ones (=C-c y P=), open with =RET= or
=o= in playlist order; =+= saves the playlist at point, =-= or =d= forgets
it, =z= shuffles it, and =b= opens it in a browser.  In the history, =d=
removes the video at point (or the region) and =D= clears the list.  In
the queue (=C-c y l=, mpv's playlist), =RET= plays an entry, =d= removes it
and =z= shuffles it.

In the subscription feed, ● marks a video you have not watched and ◆ one
that arrived since your last visit (when you last opened the feed, at
least ten minutes earlier); the header line counts them.

The channel at hand is the channel of the video at point, or the channel
whose uploads the buffer shows; its header line says whether you subscribe
to it.  Unsubscribing asks first, and removes the channel's videos from the
subscription feed.  If YouTube refuses the request, yt offers to open the
channel in its Chromium profile, to click Subscribe there.

Shuffling plays one video at once and keeps two more queued in mpv; each
time one starts, the next is fetched, so a long playlist does not send
YouTube a request per video at once.  =n= skips ahead; playing anything
else ends the shuffle.  Saved playlists live in yt's cache, not in your
YouTube account, and show how many of their videos you have not watched.

With embark, =embark-act= on a video (a completion candidate or the row at
point) offers the same keys.  With marginalia, completion candidates show
their channel, age and duration.

* History
=C-c y h= lists the videos you played in yt, the most recently played
first, with how long ago you played them and how far you got: where you
stopped, or "watched".  =RET= plays a video again, from where you stopped,
and the other video keys work too.  =d= removes the videos in the region or
at point, =D= clears the list, and =/= filters it by title or channel.
Removing a video keeps its watched mark and resume position.

The history stays in yt's cache.  With =yt-player-youtube-history= set, yt
also adds each video you play to your YouTube history, as yt-dlp's
=--mark-watched= does, so it shows on your other devices.  YouTube then
counts the video as watched to the end, and uses it for recommendations.
A video is sent once per session; problems go to =C-c y !=.

* SponsorBlock
mpv skips the segments of videos that [[https://sponsor.ajay.app][SponsorBlock]]'s community marked as
sponsors, self-promotion or reminders to subscribe, and says so in the echo
area: "Skipped sponsor (44 s)".  =C-c y U= goes back to the start of the
segment skipped last, which is then not skipped again; =C-c y K= turns
skipping off or on for the session.  The info buffer (=i=) lists a video's
segments, and which of them mpv skips.

=yt-sponsorblock-categories= chooses the categories; intros, endcards,
recaps, filler and others are off by default, and nil turns SponsorBlock
off.  yt asks SponsorBlock with curl while it resolves the streams, so
playback does not wait for it; when it cannot be reached, the video plays
without skipping.  VLC skips nothing: Emacs does not control it.

* YouTube links elsewhere in Emacs
With =(yt-url-handler-mode 1)= in your init file, =browse-url= opens YouTube
links in yt: a video plays in mpv, from the link's =t== time if it has one,
and a playlist or channel opens in a yt buffer.  That covers links in mail
(notmuch, gnus), org, help and most other buffers; eww passes only the
links matching =eww-use-browse-url= to =browse-url=.  With a prefix
argument, or when yt cannot open a link, the browser gets it as before.
yt's own "open in browser" commands (=b=) never go through the handler.
=yt-play-url= also starts at a link's =t== time.

Links come from text you did not write, so yt accepts only the YouTube
hosts, rebuilds a clean URL from the video, playlist or channel id
(dropping tracking parameters such as =si==), and never hands the link
itself to yt-dlp.  With =yt-player-youtube-history= on, a video you open
from a link is added to your YouTube history like any other you play.

* The mpv window
mpv opens its own window with the Wayland app id =emacs-yt=, so window
managers can place it.  For sway, for example:

#+begin_src
for_window [app_id="^emacs-yt$"] floating enable, sticky enable, resize set 960 540
#+end_src

or, with the Home Manager module, =programs.yt.swayWindowRule = true;= (and
=programs.yt.swayWindowCommand= to change the command), which adds:

#+begin_src nix
{ criteria.app_id = "^emacs-yt$"; command = "floating enable, sticky enable, resize set 960 540"; }
#+end_src

When the playlist ends, mpv stays open with an empty window, ready for the
next video; add =--keep-open=yes= to =yt-mpv-extra-args= to keep the last
frame instead.  =C-c y Q= closes it.  From an Emacs daemon, mpv and VLC open
on the display of the selected frame.

* Customization
=M-x customize-group RET yt= lists every option.  The most useful:

- =yt-player-backend=: =auto= (mpv if installed), =mpv= or =vlc=
- =yt-player-format=: the yt-dlp format, by default up to 1080p
- =yt-mark-watched-when=, =yt-player-watched-threshold=: when mpv counts a
  video as watched (by default after 90%)
- =yt-player-resume=: resume where you stopped
- =yt-feed-limit=, =yt-feed-refresh-interval=: how much to fetch, how often
- =yt-feed-hide-watched=, =yt-feed-hide-shorts=, =yt-feed-hide-upcoming=,
  =yt-feed-thumbnails=: the feed's defaults
- =yt-thumbs-height=: the height of thumbnails, by default 90 pixels
- =yt-sponsorblock-categories=: the SponsorBlock segments mpv skips
- =yt-save-minibuffer-history=: let =savehist-mode= keep what you type at
  yt's prompts
- =yt-player-youtube-history=: add the videos you play to your YouTube
  history
- =yt-cookie-profile=: the Chromium profile, instead of choosing it with
  =yt-login=

* Privacy
- *Network:* yt-dlp talks to www.youtube.com (pages, the API the pages use,
  and the player script, run locally by its JavaScript runtime).  Players
  fetch the video streams from googlevideo.com.  Thumbnails come from
  i.ytimg.com, through curl, without cookies.  Subscribing and
  unsubscribing send one request to www.youtube.com through curl, with the
  cookies.  With =yt-player-youtube-history= set, yt-dlp also tells
  YouTube about each video you play.  Before mpv plays a video, and when its details are shown, curl
  asks sponsor.ajay.app for SponsorBlock segments, without cookies, naming
  only the first 4 characters of the SHA-256 hash of the video id, which
  many videos share.  There is no telemetry and no self-update.
- *Cookies:* only those of the chosen profile, only for youtube.com, in a
  mode 0600 file under =~/.local/state/yt/=.  Every yt-dlp run gets its own
  private copy in =$XDG_RUNTIME_DIR/yt/=, deleted afterwards; so does curl
  when it subscribes, along with a mode 0600 config file holding the
  request's headers, so nothing derived from the cookies is in the process
  list.  Cookie values
  are never logged or shown.  =M-x yt-logout= deletes the files; signing out
  of YouTube in the profile ends the session itself.
- *Local data:* the videos you played, watched marks and resume positions
  are in a mode 0600 SQLite file next to the cookies;
  =M-x yt-forget-history= clears them all.
  Only a fixed set of video fields is stored, never yt-dlp's raw output,
  which holds stream URLs signed for your IP address.  Those are kept in
  memory only, for mpv, until shortly before they expire, and forgotten
  on =yt-logout=.
- *Logs:* =*yt-log*= lists the commands yt runs and how long playing took,
  by video id, with search queries replaced by =REDACTED=, stream URLs by
  =<stream URL>= and authorization headers and cookies by =<redacted>=; it
  keeps the last 300 000 characters.  While a search runs, its query is
  visible to other local users in the process list.  =yt-doctor= shows no
  cookies, tokens or titles, but its file names show your user name.
- *Prompts:* searches, filters and URLs typed at yt's prompts have their
  own histories, which =savehist-mode= does not save unless
  =yt-save-minibuffer-history= is set.
- *mpv:* its control socket, which accepts any mpv command, is in the mode
  0700 runtime directory; yt never falls back to a shared directory.

* Known limitations
- The subscription feed has no exact upload times, only YouTube's "3 hours
  ago", so ages are approximate until you open a video's details.  The
  order is YouTube's.  Shorts have no channel or time of their own.
- A refresh stops after 10 videos it already knows; premieres and streams
  that YouTube moves in the feed can be missed until =G=.
- VLC is not controlled: it marks a video as watched when it starts, and
  cannot queue.
- mpv needs yt to resolve every stream first, which takes a few seconds:
  YouTube releases streams only a few seconds after yt-dlp asks for them.
  yt keeps the resolved streams in memory, so playing or resuming a video
  again within a few hours starts at once.
- Stream URLs expire after some hours; a queued video that fails is
  resolved again, once.
- Subscribing uses YouTube's internal API, which is not documented, the
  way the website's Subscribe button does; it can break when YouTube
  changes, independently of yt-dlp.  Then the Chromium fallback still
  works.
- Everything depends on yt-dlp keeping up with YouTube: update it when
  =yt-doctor= says it is old, or when fetching suddenly fails.

* Development
All builds and tests use the Emacs from this flake, not the Emacs installed
on the host, and run with =HOME= and the XDG directories in a temporary
directory, so they cannot touch real cookies, caches or customizations.
yt-dlp, the cookie exporter, mpv, VLC and curl are replaced by scripted
fakes in =test/bin=; the tests use no network.

#+begin_src sh
nix develop            # shell with the test Emacs, mpv, yt-dlp, vlc, jq, curl
make all               # compile, checkdoc, lint, test (inside nix develop)
make test SELECTOR='"yt-feed-.*"'   # run a subset of the tests
nix run .#test         # same as `make test`, without entering the shell
nix run .#test -- lint # any make target
nix flake check        # every check, plus the tests with compiled code
YT_LIVE=1 nix run .#smoke  # a few checks against the real YouTube
#+end_src

=make= refuses to run unless =YT_EMACS= points at the flake's Emacs.
=nix run .#smoke= is the only thing that talks to YouTube: with the
sandbox's sign-in, it checks the yt-dlp version, the session, five feed
entries and the fields yt reads from them, resolving one stream and
SponsorBlock, printing counts only.  It changes nothing in the account and
refuses to run without =YT_LIVE=1= or under CI.

** Sandbox Emacs
#+begin_src sh
nix run .#sandbox
#+end_src

This opens a GUI Emacs that is separate from the host Emacs and its daemon:
default Emacs plus yt.  It starts with =-q --no-site-file=, so it reads none of
the host's config (=~/.emacs.d=, =~/.emacs=, =default.el=, the Nix profiles'
=site-lisp=).  Its only config is [[file:sandbox/init.el][sandbox/init.el]], which loads yt from the
working tree with generated autoloads and binds =C-c y= to =yt-map=.

Emacs keeps its own files in =.sandbox/emacs.d=.  yt keeps its state (the
sandbox's cookies included), cache and runtime files in the =yt-sandbox=
directories of =$XDG_STATE_HOME=, =$XDG_CACHE_HOME= and =$XDG_RUNTIME_DIR=:
outside the checkout, so that no build, archive or search of the
repository picks up the cookies; the sandbox refuses to start on the host
yt's state.  The flake's mpv, yt-dlp, vlc, curl and
=yt-export-cookies= come first on =PATH=.
